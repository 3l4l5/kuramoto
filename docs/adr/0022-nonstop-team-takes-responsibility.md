# ADR-0022: ノンストップで進め、チームで責任を持つ(merge もチームが行う)

- 状態: 提案
- 日付: 2026-11-10

## 背景

責任者が求めているのは、基本的に止まらずに進み、チームでできるだけ責任を取ることだった。ところが実際のプロジェクトでは、次のところで止まっていた。

- **merge**: 責任者が押すまで merge されず([ADR-0013](0013-owner-presses-merge.md))、後のチケットはその merge を待って着手できなかった(#10 で #11〜#15 が止まった)。
- **リーダーの判断**: 仕様の判断(例: CI で使う MySQL の版)を責任者に上げ、答えが来るまで(または期限まで)止まっていた。
- **予算**: チケット 1 枚の予算(既定 $5)を使い切るたびに、責任者に「続けるか」を聞いて止まっていた。
- **詰まったとき**: リーダーの手助けが「助言してやり直す」か「保留」しか無く、担当を替える・チケットを分けるといった手が無かった。

## 決定

- **merge はチームが行う**(設定 `auto_merge`、既定は自動)。merge 待ちのチケットを 20 秒ごとに見回り、確認がすべて済み・CI が緑・衝突なしなら merge する。CI の途中なら 1 分ほど空けて確かめ直す。CI が失敗していれば持ち主に戻し、衝突していれば持ち主に直させる(確かめ方は ADR-0013 と同じ)。merge したら、待っていた後のチケットがすぐ動けるように受信箱を見直す。責任者も画面から今すぐ merge できる。
- **ノンストップ**(設定 `nonstop`、既定は有効)。
  - 戻せる判断は、リーダーが決める。責任者に上げる道具は断られ、決めるように返される。分からない点は仮に決め、その前提を理由に、担当への指示をチケットのメモに残す。決めたことは、リーダーとのチャットで責任者に報告する(止めずに、違えばあとから指示してもらう)。
  - 責任者に上がって止まるのは、取り消せない操作と、責任者にしかできないこと(秘密情報やアカウントの登録・契約・権限の付与)の保留だけ。
- **詰まったときの手助けを増やす**。リーダーは、助言してやり直す・別のメンバーや島に渡す・残りを別チケットに切り出して範囲を絞る、のどれかで解く。保留は責任者にしかできないことが要るときだけ。続けて 5 回手助けしても進まなければ保留する。
- **予算**: 新しいプロジェクトは、チケット 1 枚の予算を無制限から始める。止める歯止めは、責任者が決める全体の予算と島の予算で掛ける。

## 結果

- 責任者が何もしなくても、チケットは merge まで進み、後のチケットも続けて動く。
- 責任者の仕事は、全体の予算を決めることと、リーダーからの報告を読んで違うものに指示すること、責任者にしかできない対応(保留)になる。
- main には、チームの確認と CI を通ったものが責任者の確認なしに入る。CI と確認の質がそのまま main の質になる([ADR-0021](0021-review-blocks-only-on-acceptance-security-regression.md) の基準と、リポジトリの CI が大事になる)。
- 責任者が押す運用に戻したいプロジェクトは、プロジェクトの設定で「チームが自動で merge する」「ノンストップで進める」を外す。

## 検討した別案

- **merge は責任者のまま、後のチケットを承認済みのブランチに積んで先に進める**: 止まりは減るが、先のチケットが差し戻されると後のチケットも直しが要る。merge 待ちが溜まり続ける問題も残る。
- **判断の期限を短くする**: 待ち時間は減るが、責任者が答えない前提の仕組みになり、リーダーが責任を持って決めることにはならない。
