# ADR-0057: 画面は試作と描画で見比べて合わせ、試作が見本用・実装と食い違うところは理由を書いて変える

- 状態: 提案
- 日付: 2026-11-14
- チケット: #37(チケットの詳細を 1 枚の画面に)・#80(全画面の見比べ)・#82(編成「島」タブ)・#84・#86・#88(共通ヘッダーと地)
- 関係: ADR-0033(試作を渡して見比べる)・ADR-0034(デザインシステムと画像の見比べ)・ADR-0018

## 背景

ADR-0033・0034 で、企画の試作を担当に渡し、描画した画像をお手本と見比べる(`render_page`・`compare_screen`)ことにした。実際に全画面を見比べると、静的な点検では見えなかったずれ(スマホで引き出しが全画面にならない・件数の札の色・ヘッダーの形)が見つかった。一方で、試作は 1 つの幅だけ・見本用の項目・画面によって食い違う作り(ヘッダーの帯が白いものと無いもの)を含み、そのまま真似できないところがある。

## 決定

- 画面は、試作の画像と、描画した画像(`render_page`)の見比べ(`compare_screen`)で合わせる。**違いの割合の目安は 10% 以下**。直す前・直した後・試作を `docs/screenshots/<チケット番号>/` に残し(README に撮り方と、直したもの・直していないもの)、撮り直せる形にする。
- **試作が食い違うときは、多数の試作に合わせ**、合わせない所は「試作との違い」として README と PR の本文に理由を書く。
  - 共通ヘッダー(#84・#86・#88): 行き先を**切り替えスイッチ**にし、全画面で同じ形・同じ位置にする。ページの背景は灰(`--bg`)、ヘッダーと部品(カード・パネル・引き出し)は白(`--surface`)。パソコンのヘッダーは**帯なし**(多数の試作どおり)、スマホは**白い帯**(スマホの試作どおり)。編成の版の札・始業中の表示を出す。
  - 試作に無いもの(企画スタジオ・生産性・設定の行き先は試作のスイッチに無い)は、リーダーのメモに従って**同じスイッチの右に足す**(ここは試作と違う)。企画スタジオ・設定は試作が無いので、共通ヘッダーと地だけを合わせる。
  - 編成「島」(#82): 試作は上に重なる窓だが、実装は**右の列の引き出しのまま**にする(連絡経路の保存前の案を床に重ねて見せるので、窓で覆わない。ADR-0055)。試作の項目(役割の選択・応援の条件など)は見本で、実際の編成の項目とは違うので、実際の項目を使う。
  - チケットの詳細(#37): モーダルをやめ、共通ヘッダーと帯のある **1 枚の画面**にする。
- 試作の HTML・CSS を貼り付けない。**トークンと共通の部品**で組み立てる(ADR-0034)。試作が 1 つの幅しか無いときは、反対の幅も撮って崩れを確かめるが、試作が無いものは「未計測」と書く。
- 撮影のために、引き出しを URL(`?drawer=formation|policy|lead&dtab=`)で開けるようにする。開け閉めしたら捨てる。

## 結果

- 画面のずれが、描画で見えるうちに直る。食い違いは理由つきで残り、次の人が同じ迷いをしない。
- 試作が見本用の部分を、そのまま作って実際と合わなくなることがない。

## 検討した別案

- **試作どおりに作る**: 試作の食い違い(帯の有無・スイッチの色の向き)がそのまま入り、実装の都合(経路の案を床に重ねる)に合わない。
- **試作を使わず、トークンだけで作る**: 並び・文言・余白がずれる。
- **静的な点検(コードの検索)だけで合わせる**: 描画しないと見えないずれ(全画面にならない・隠れる)が残る。
