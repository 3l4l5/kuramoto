# ADR-0033: 企画で合意した画面の試作を、作る人と確かめる人に渡して見比べる

- 状態: 提案
- 日付: 2026-11-12

## 背景

企画スタジオで画面の試作(HTML)を作って合意しても、開発・レビュー・QA に渡していたのはチケットのタイトルと本文だけだった。チケットにはひも付けた画面の key が入っていたが、試作そのものは誰にも渡らず、出来上がった画面を試作と見比べる人もいなかった。そのため、完成した画面が想定のデザインと大きく違っていた。設計書をリポジトリに置く話([ADR-0014](0014-design-docs-in-workspace-repo.md))も、まだ作っていない。

## 決定

- チケットに関わる画面の試作を、開発・レビュー・QA の作業場所の `.kuramoto/design/<画面>.html` に置く。関わる画面は、チケットにひも付けた画面と、チケットの要件をひも付けた画面。案が複数あれば選んだ案(無ければ最初の案)。`.kuramoto/` は git の info/exclude に足し、コミットされないようにする。
- 担当への指示に「画面のデザイン」の節を足す。
  - 開発: 試作に合わせて作る(並び・要素・文言・色・余白・大きさ)。リポジトリにあるデザインの決まりで表現してよく、HTML をそのまま貼る必要はない。作ったらスクリーンショットを撮って試作と見比べてから報告する。理由があって違えたところは PR の本文に書く。
  - QA: 実装した画面と試作を同じ大きさでブラウザに開いてスクリーンショットを撮り、見比べる。違いは受け入れ条件の指摘にする(PR に理由が書かれた違いと、1〜2px のずれは除く)。
  - レビュー: 差分の画面のコードが試作と食い違っていないか(要素の抜け・文言・並び)を見る。
- セキュリティには渡さない。

## 結果

- 画面のあるチケットは、試作との違いが QA の指摘になり、合うまで差し戻される。
- QA の起動が、スクリーンショットを撮って見比べる分だけ長くなる。
- 既に merge した画面は変わらない。合わせ直すには、別にチケットを作る。

## 追記: 試作の食い違いの決め方・全画面の試作・切り出しの引き継ぎ

- 試作と実装が食い違うときの決め方、見比べの目安(10% 以下)・残し方は ADR-0057。
- 切り出したチケットは、親の画面・要件・リポジトリ・要件の項目を引き継ぎ、`plan_refs` の `allScreens` で全画面の試作を渡せる。デザインシステムがあれば、画面にひも付かないチケットの作業場所にも `tokens.css` などを置く(#77。ADR-0044)。
