# ADR-0048: リーダーは GitHub の PR・CI・merge の状態を「読むだけ」の道具で見る

- 状態: 提案
- 日付: 2026-11-14
- チケット: #56

## 背景

リーダーは「この PR は merge できるか」「CI はなぜ落ちたか」を知りたい。しかし、リーダーの作業場所は閉じ込められていて(ADR-0020)、`gh` も GitHub API も認証つきでは使えない。作業場所の外に出ているのは Kuramoto 本体の GitHub への接続だけで、そこには書き込みの口(merge・コメント・CI の再実行など)もある。merge は責任者が行う(ADR-0013)ので、リーダーが書き込めてはいけない。

## 決定

- Kuramoto 本体が持っている GitHub への接続で、PR の merge の可否・できない理由・CI の各チェック・レビューを**読んで答える**道具をリーダーに渡す(`src/project/github-read.ts`)。
- 渡すのは読み取りの口(`GitHub` の `prDetail` だけ。型は `Pick<GitHub, "prDetail">`)で、**merge・push・コメント・ラベル・CI の再実行・Actions の切り替えといった書き込みの口は、型の上でも渡さない**。
- 閉じ込め(`confine.ts`)は変えない。トークンも `~/.config/gh` も作業場所には出さない。
- 会話に出る本文は、万一トークンが混ざっても伏せ(`(トークンは伏せました)`)、長いものは 12,000 字で切る。
- merge の判断(押すこと)は責任者のまま(ADR-0013・ADR-0022)。リーダーは状況を見て責任者への報告・チケットの手当てに使う。

## 結果

- リーダーが、外のサイトを開かずに、merge 待ちの PR の状態を答えられる。見回りの PR 取り直し(ADR-0026 の追記)も同じ接続を使う。
- リーダーが merge や書き込みをできる経路は増えない。

## 検討した別案

- **リーダーの作業場所に GitHub のトークンを渡す**: 閉じ込め(ADR-0020)を破り、書き込みも可能になる。
- **閉じ込めの通信の許可に api.github.com を足す**: 認証が要り、トークンが作業場所に入る。
- **リーダーに書き込みも含めて GitHub の口を渡す**: merge は責任者が押す決め(ADR-0013)に反する。型に書き込みを含めなければ、後から口が混ざらない。
