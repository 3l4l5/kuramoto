# ADR-0034: デザインシステムを企画の成果物にし、画面を画像で見比べる

- 状態: 提案
- 日付: 2026-11-12

## 背景

試作を担当に渡すようにしても([ADR-0033](0033-match-screen-design.md))、画面ごとに寄せ合うだけでは揃わない。実際のプロダクトでは:

- 色・文字・余白・部品の共通の決まりが無く、担当が画面ごとに見た目を決めていた。試作の側も画面ごとに別の `<style>` で、画面どうしで揃っていなかった。
- スタジオがスマホの試作を幅 230px の枠で描かせていたので、試作が実際のスマホ(幅 390px)の 6 割ほどの大きさで作られていた。実装と合うはずがなかった。
- 違うかどうかを、言葉でしか確かめていなかった。

## 決定

- **デザインシステムを企画の成果物にする**。画面デザインの段階で、デザイナーが先に `set_design_system` で、方針・トークン(色・文字・余白・角丸・影を CSS 変数の名前と値にしたもの)・部品(見た目の HTML と状態)を書く。試作はトークンと部品で組み立てる。画面があるのにデザインシステムが無ければ、画面デザインの段階は合意できない。スタジオに見本(色見本・部品)を出す。
- **試作は実際の端末の幅で作る**(スマホ 390px・パソコン 1280px)。スタジオでは縮めて見せる。
- **引き渡しで、最初のチケットをデザインシステムの土台にする**。トークンを CSS 変数に、部品を共通の部品にし、トークン・部品・各画面を並べたカタログ(開発のときだけ開く `/_design`)を**プロダクトのリポジトリ**に作る(成果物なので)。画面を作るチケットは、このチケットの後に並べる(`after`)。
- **担当に渡すもの**: 試作の HTML に加えて、デザインシステム(`design-system.json`・`tokens.css`・部品の見本 `components.html`)と、試作を実際の幅でブラウザに描いた**お手本の画像**(`<画面>.png`)。トークンだけを使い、画面ごとに値を作らないよう指示する。
- **画像で見比べる**: 開発と QA に `compare_screen` を渡す。担当が撮った実装のスクリーンショットを、Kuramoto がお手本と比べ、違う画素の割合と、違うところを赤く塗った画像を返す。QA は違いが 10% を超えるか、要素・文言・並びが違えば指摘にする。チケットの画面に「お手本 / 実装 / 違い」を並べる。
- **画像の置き場所**: 画像そのものはデータの置き場所の `design/` に置き、DB(`design_images`)には置き場所・大きさ・違いの割合だけを残す。置き場所は `DesignStore` で差し替えられ、S3(FastFS など)に替えられる。試作の HTML とデザインシステムは、これまでどおり DB(企画の中身)に置く。

- **画面の描画はサーバが行う(`render_page`)**: 担当の作業場所(サンドボックス)の中ではブラウザを起動できない([ADR-0020](0020-confine-agents-to-worktree.md))ので、開発と QA に `render_page` を渡す。担当がアプリ(`npm run dev` など)を動かし、そのローカルの URL(`http://localhost:…`・`127.0.0.1`・`[::1]`)か、作業場所の HTML(試作など)と、幅(390 か 1280)を渡すと、サーバがブラウザで描き、ページ全体の PNG を作業場所の `.kuramoto/design/shots/<name>-<幅>.png` に置く(git には入らない)。それを `compare_screen` に渡せば、お手本と比べられる。
  - 描く URL は、この機械の中の http(s) だけに絞る。描いている間も、ページが読みに行く先は、この機械の中(と `data:`・`blob:`)だけで、外へは出ない。`file:` と作業場所の外のファイルは描かない。担当は、もともとローカルのポートに届く(ADR-0020)ので、これで見られるものは増えない。
  - お手本の画像と同じ `playwrightRenderer` の作りで描く(`design-visual.ts`)。サーバの側に Chrome(または Playwright の Chromium)があれば動く。
  - 合意した試作の HTML・お手本の画像・デザインシステムは、これまでどおり作業場所の `.kuramoto/design/` に置き、その場所を環境変数 `KURAMOTO_DESIGN_DIR` で担当に渡す。

## 結果

- 色・文字・部品が、企画・試作・実装で同じ決まりになる。
- 違いが数字と画像で残り、責任者もチケットで確かめられる。
- お手本の画像を描くのに、手元の Chrome(無ければ Playwright の Chromium)を使う。描けないときは画像の見比べを飛ばし、試作の HTML だけを渡す。
- 前に作った試作は幅 230px で作られているので、実際の幅で見ると小さく偏る。合わせるには、デザイナーに実際の大きさで作り直してもらう。
