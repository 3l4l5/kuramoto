# ADR-0036: 作業場所を片付け、ディスクと同時実行を見張って PC を守る

- 状態: 提案
- 日付: 2026-11-13

## 背景

チケットごと・役割ごとに作る作業場所(git worktree。ADR-0001)を、消す処理がなかった。チケットが終わっても `~/.kuramoto-work` に残り続け、ある環境では worktree が 847 個・96GB になった(うち node_modules が 440 個・約 65GB)。ディスクの空きが 5GB 台まで減ったところで、担当が一斉に npm install などで書き込み、Mac がフリーズしてウォッチドッグに再起動された。

## 決定

- **作業場所の片付け**: 起動時と 10 分ごとに、終わったチケットの作業場所(`worktrees/<番号>-<役割>`)を消し、元の clone で `git worktree prune` する。
  - merge 済み(done)のチケットは、すべて消す。
  - 取りやめ(dropped)は戻せる(`reopenTicket`)ので、開発の作業場所は push 済みで変更が残っていないときだけ消す。残すときも node_modules は消す。
  - いま担当が動いているチケットと、企画の担当の場所(`plan-<役割>`)は触らない。
- **ディスクの見張り**: 作業場所のディスクの空きが下限(`KURAMOTO_MIN_FREE_GB`、既定 15GB。0 で見張らない)を切っている間は、新しいチケットの仕事を始めない(企画スタジオとチャットなど、チケットを持たない仕事は動く)。切ったときと戻ったときに、リーダーのチャットで知らせる。切ったら、すぐ片付けも走らせる。
- **同時実行の上限**: すべてのプロジェクトを合わせて、同時に起こすエージェントの数を絞る(`KURAMOTO_MAX_RUNS`、既定 3)。プロジェクトごとの上限(島の席の数・設定 `concurrency`)はそのまま効き、低い方で止まる。

## 結果

- 作業場所が際限なく増えなくなり、ディスクが埋まって PC ごと止まることを防げる。
- 取りやめたチケットを戻したとき、開発の作業場所が消えていれば、push 済みのブランチから作り直す(push していない変更は消さないので失わない)。node_modules は入れ直しになる。
- 同時に動く担当が減るので、席の多い編成ではチーム全体の進みが遅くなる。速さを取るなら `KURAMOTO_MAX_RUNS` を上げる。
