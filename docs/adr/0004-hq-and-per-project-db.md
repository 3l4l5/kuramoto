# ADR-0004: 本部とプロジェクトの 2 層に分け、DB をプロジェクトごとに持つ

- 状態: 承認
- 日付: 2026-11-07

## 背景

1 つのチームが 1 つのプロダクトの面倒を見る形にしたい。プロジェクトごとにコンテキストが混ざらないことが目的。一方で、プロジェクトの作成・リポジトリの登録・要件定義を行う上位の層も欲しい。

## 決定

- 本部(1 つ)とプロジェクト(複数)の 2 層に分ける。DB は本部に 1 つ + プロジェクトごとに 1 つ。
- 1 つのプロジェクトに GitHub のリポジトリを複数登録できる。
- データはリポジトリの外(`~/.kuramoto/<owner>/<repo>/`)に置く。DB・worktree・セッションをプロジェクトごとに閉じる。
- エージェントには責任者個人の Claude の設定やメモリを読ませない。
- 本部の一覧に出す数字は本部に写さず、各プロジェクトの DB を読みに行く。

## 結果

- プロジェクトをまたいで文脈が混ざらない。障害も隣に響かない。
- 全プロジェクトの「あなたの対応」は本部で集める必要がある。
- レート制限(Claude・GitHub)はプロジェクト間で共有なので、全体の同時起動数の上限を本部に置く(2 つ目を同時に動かしたくなってから)。

## 検討した別案

- **1 つの DB に全プロジェクトを同居させる**: 集計は楽だが、文脈を分ける目的に反する。
