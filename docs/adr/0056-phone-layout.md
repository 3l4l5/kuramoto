# ADR-0056: スマホ(390px)は CSS のメディアクエリで組み替え、下のタブ・全画面の引き出し・1 列の画面にする

- 状態: 提案
- 日付: 2026-11-14
- チケット: #12(対応・ボード・チケットの詳細)・#13(引き出し・開発ルール・停車番号)・#87(引き出しのタブ)・#92(メニューから「チームの方針」)
- 関係: ADR-0035(責任者が外から使える)・ADR-0055(オフィスの路線図)

## 背景

画面はパソコンの幅(1280px)で作られていて、スマホでは、ボードの列・引き出し・チケットの詳細が横にはみ出し、操作できなかった。責任者は出先から「あなたの対応」(承認・merge)をしたい(ADR-0013)。

## 決定

- 画面は**同じ部品を、CSS のメディアクエリで組み替える**(別のコンポーネントを作らない)。
- **下のタブ**「対応 / オフィス / リーダー / メニュー」とメニューのシートを足す。上の切り替えスイッチと、引き出しのボタンはスマホでは隠し、下のタブとメニューが同じ行き先を持つ。メニューから「チームの方針」を押したときは、オフィスの画面へ移ってから引き出しを開く(引き出しはオフィスの画面にだけ描かれるため。#92)。
- **ボード**: 工程を上のタブ(件数つき)にして 1 列ずつ見る。開発より前の工程は点線(ADR-0044)。
- **チケットの詳細**: 1 列にして「やりとり / 中身」のタブにし、メモの欄は下に固定する。帯に、種類のチップ(押すと種類を選ぶ)・金額・要件・PR のチップを出し、戻るは「‹ ボード」。
- **引き出しは全画面**にし、下のタブ(高さ 57px)の上までにする(下のボタンが隠れない)。部品が `aside` でも `section` でも全画面にする。編成の引き出しの「島・連絡経路・流れ」のタブが潰れないようにする(#87)。開発ルールは一覧 → 編集の 2 画面(ADR-0054)。
- オフィスの停車番号は、受け口を 0 にする。始業/終業は表示だけにする。
- オフィス/ボード/ツリーの切り替えは、スマホの試作どおり、幅いっぱいの均等幅のセグメントにする(ADR-0057)。
- 確かめは、Playwright の 390px のテスト(下のタブとメニュー経由の操作。ADR-0053)で行う。

## 結果

- 画面がスマホで横にはみ出さず、対応・ボード・チケットの詳細を出先で扱える。
- 部品が 1 つなので、パソコン側の直しがスマホにも届く。

## 検討した別案

- **スマホ専用の画面(別のコンポーネント)を作る**: 2 つの画面を直し続けることになる。
- **パソコンの画面を縮小して見せる**: 文字・ボタンが小さく、押せない。
- **スマホでは責任者の対応だけを見せる**: ボード・チケットの詳細が見られず、状況が分からない。
