# ADR-0050: プロジェクトは名前を打たせて削除でき、DB・作業場所・データの置き場所を消す(GitHub には触れない)

- 状態: 提案
- 日付: 2026-11-14
- チケット: #62(削除)・#69(データの置き場所の片付け)・#70(リポジトリ名のチェック)

## 背景

プロジェクトは作れたが、消せなかった。いらなくなったプロジェクトの行・作業場所・clone・画面の画像などが残る。1 つの database に複数のプロジェクトが入る(ADR-0037・0038・0040)ので、消し方を間違えると別のプロジェクトの行を消しかねない。データの置き場所(`data_dir`)は `join(home, owner, repo)` で決まるので、owner・repo に `.` や `..` が通ると、home の外や owner のディレクトリを指して、消す先を誤る。

## 決定

- `DELETE /api/projects/:id` と、設定画面の「このプロジェクトを削除」を足す。確認ダイアログで**プロジェクト名を打たせて**から消し、ホームに戻る。文言に「画面の画像などのファイル」も消えることを書く(#69)。
- 削除の前に、ディスパッチャ・merge の見回り・走っているメンバーの起動を止める(`Dispatcher.stopAll`)。
- DB は `project_id` で絞り、`project_id` を持つ**全部の表の行を 1 トランザクションで消す**。別のプロジェクトの行には触らない(ADR-0040 の見張りに載る)。
- **作業場所を消す**: worktree と Kuramoto の clone。失敗しても DB の削除は止めず、ログに残す。
- **データの置き場所(`data_dir`)も消す**(#69)。SQLite を閉じたあとで `data_dir` ごと消す。同じリポジトリで作り直すと、元の置き場所が使われる。
- **GitHub には触れない**(リポジトリ・PR・Issue は消さない・閉じない)。
- **リポジトリ名のチェック**(#70): `.` と `..` だけの owner・repo を断る。判定は `src/domain/repo-name.ts` にまとめ、`createProject`・`updateProject`・`addRepo` と画面の書式チェックで使う。

## 結果

- いらなくなったプロジェクトを、画面から、取り残しなく片付けられる。
- 名前を打たせるので、誤クリックで消えにくい。
- DB を消す側が `project_id` で絞るので、同じ database の別プロジェクトに及ばない。

## 検討した別案

- **削除ではなく「アーカイブ」(隠すだけ)にする**: データと作業場所が残り続ける。消したいという要望に応えない。
- **GitHub のリポジトリも閉じる・消す**: 取り消せない操作で、Kuramoto のデータとは別物。責任者が GitHub で行う。
- **作業場所の削除に失敗したら DB も消さない**: 消せない作業場所のせいで、プロジェクトが消えなくなる。DB は消し、失敗はログに残す。
- **`data_dir` を残す**: 画面の画像などが残り続ける。同じリポジトリで作り直せば同じ置き場所を使うので、残すと古いファイルが混ざる(消す)。
