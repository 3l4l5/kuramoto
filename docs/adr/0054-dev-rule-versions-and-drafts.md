# ADR-0054: 開発ルールは版を持ち、編集中の下書きは「別のルールを選ぶ・閉じる」では確かめ、別の画面へ移っても残す

- 状態: 提案
- 日付: 2026-11-14
- チケット: #30(版・編集・削除)・#32(別のルールを選ぶときの確かめ)・#33(引き出しを閉じる・移るときの確かめ)・#40(画面を移っても下書きを残す)
- 関係: ADR-0011(開発ルールは形式で確かめられるものを優先する)

## 背景

開発ルール(ADR-0011)は、足す・有効/無効にするだけで、直す・消す・前の版を見ることができなかった。編集を入れると、書きかけ(下書き)が、別のルールを選んだり、引き出しを閉じたりしたときに、無言で消える・残るの問題が出る。引き出し(チームの方針)はオフィスの画面にあり、ほかの画面(生産性・設定・企画スタジオ)へ移ることもある。

## 決定

- **ルールに版を持たせる**。`dev_rule_versions` と `dev_rules.deleted_at`(削除は消さずに印を付ける)を足し(マイグレーション 20)、**足す・直す・消す・有効/無効にするたびに版が上がる**。API は `POST /dev-rules/:id`(直す)・`POST /dev-rules/:id/delete`(消す)で、一覧に `version` を返す。画面は、見出しの版の札、選んだルールの編集、下の帯の「保存して vN にする」、「このルールを消す」。
- **下書きがあるときに、ほかのルールを選ぶ・「ルールを足す」を押すときは、捨ててよいか確かめる**(#32)。引き出しを閉じる・別の引き出しへ移るときも同じ確かめを出す(#33)。下書きは、引き出しの外(`App`)で持つ。
- **ほかの画面へ移っても、下書きは残す**(#40)。生産性・設定・企画スタジオ・本部へ移っても引き出しと下書きを残し、戻ると続きから直せる。ブラウザの戻る・進むでも移るため、確かめるより**残す**ことにした。**別のプロジェクトを開いたときだけ空にする**(`useDrawerState` の `resetKey` を、画面の名前から今のプロジェクトの id に変える)。
- スマホ幅では、開発ルールは一覧 → 編集の 2 画面にし、変更が残ったまま「+ ルールを足す」を押したら、編集の画面で捨ててよいかの確かめを出す(ADR-0056)。

## 結果

- 書きかけが、操作の取り違えで消えない。別のプロジェクトのルールの下書きが混ざることもない。
- 版が上がるので、いつ何が変わったかが残り、生産性のルール違反の数(ADR-0011)と突き合わせられる。

## 検討した別案

- **上書き保存で版を持たない**: 直した履歴が残らず、違反数の変化が何のルールの変更によるかを追えない。
- **画面を移るたびに捨ててよいか確かめる**: 戻る・進むで移ることもあり、確かめだらけになる。引き出しを閉じる・別の引き出しへ移るような、明示の操作のときだけ確かめる。
- **下書きをすぐ捨てる(確かめず)**: 書きかけを失う。
- **別のプロジェクトを開いても下書きを残す**: 別のプロジェクトのルールに、前のプロジェクトの下書きが重なる。
