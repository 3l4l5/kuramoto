# ADR-0008: 企画を段階に分け、段階ごとに合意・お任せ・省くを選べるようにする

- 状態: 承認
- 日付: 2026-11-07

## 背景

チャットで要件を聞いて箇条書きにするだけでは、画面デザインやユーザーフローを考えられず、何に合意したのかも残らない。一方で、すべてを責任者が確かめるのは重い。

## 決定

- Kuramoto の中に企画スタジオを作る。段階は 要件 → ユーザーフロー → 画面デザイン → ドメインとデータ。(後に画面デザインの次へインフラを足した。[ADR-0015](0015-infra-stage.md))
- 要件は受け入れ条件付き。フローは図。画面は AI が作る触れる試作(複数案)で、画面上を指してコメントする。
- 企画・デザイナー・アーキテクトの 3 人で回す。
- 段階ごとに進め方を「合意する」(既定)・「お任せ」(AI が決めて報告。戻せない変更だけは聞く)・「省く」(実装中に決める)から選ぶ。要件は省けない。
- すべての段階が終わると「チームに渡す」。チケットに要件の項目・画面・設計の節と、進め方(お任せ・省略)をひも付ける。
- 途中で機能を足すときは要件の版を上げる。今の要件の範囲に収まる修正はチケットだけで足りる。
- ユーザーフローは「AI が描く → 責任者が言葉で直す → AI が抜けを指摘する」を先に作り、図を直接いじるエディタは後から足す。

## 結果

- 何に合意したかが版として残り、後の工程(レビュー・QA)の基準になる。
- 省いた・お任せにした段階の影響を、手戻りの指標で後から比べられる。

## 検討した別案

- **外部ツール(Figma・ドキュメント)に任せ、リンクだけ管理する**: 作る量は少ないが、AI が作った試作を直す流れが外に出て、チームとのつながりが弱くなる。
