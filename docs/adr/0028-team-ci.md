# ADR-0028: チームの CI を持ち、使うときは GitHub Actions を止める

- 状態: 提案
- 日付: 2026-11-12

## 背景

merge の前に GitHub Actions の CI を待っていた。待つたびに数分かかり、落ちれば持ち主に戻り、直してはまた待つ。さらに、アカウントの Actions の利用枠が $0 で止まり(Usage blocked)、どの PR の CI も始まらず、merge が全部止まった。担当は作業場所で lint・型・テストを動かしているが、それは誰も確かめておらず、merge の判断には使えなかった。

## 決定

- プロジェクトの設定「CI」で、**チームの CI を使う**か **GitHub Actions の CI を待つ**かを選べるようにする(設定 `ci_mode`。既定は GitHub Actions)。
- チームの CI では、Kuramoto が確認のコマンドを流す。
  - **流すもの**: リポジトリごとに設定したコマンド(1 行に 1 つ)。空なら package.json と lock ファイルから決める(入れる → lint → 型 → テスト)。
  - **流す状態**: PR のブランチ(push 済みのもの)を、最新の main と合わせたもの。合わせられなければ衝突として持ち主に戻す。
  - **流す場所**: この PC の、チケットごとの確認用の作業場所(`worktrees/<番号>-ci`)。PR の中身はエージェントが書いたコードなので、エージェントのシェルと同じ閉じ込め(Claude Code と同じ `@anthropic-ai/sandbox-runtime`。ADR-0020)の中で流す。ホームの下はツールチェーンと作業場所のほかは読めず、認証情報・Kuramoto のデータは読めず、通信は許したドメインだけ、トークンの環境変数は渡さない。1 度に 1 つずつ、1 コマンド `team_ci_timeout_min`(既定 20 分)まで。
  - **流すとき**: 担当が submit_pr して Kuramoto が push したあと、レビューの前。落ちたら(最初に落ちたところで止め)出力の末尾を付けて、その場で持ち主に戻す。落ちる PR にはレビューの手間をかけない。
  - **merge の直前**: 通ったときから PR のコミットも main も変わっていなければそのまま merge する。main が進んでいれば、新しい main と合わせて流し直す(merge キューの代わり)。
  - merge は GitHub の CI を見ない。
- チームの CI に切り替えると、リポジトリの GitHub Actions を止める(`PUT repos/<repo>/actions/permissions enabled=false`)。戻すと動かす。止められなければ(権限が無いなど)、チームの CI には切り替えたうえで責任者に知らせる。
- チームの CI を使う間は、GitHub Actions の CI のために作ったチケット(「main の CI を直す」。ADR-0027)を、理由を付けて自動で取りやめる(切り替える前に作られたものも)。GitHub の CI が動かないという知らせも消す。GitHub の CI を調べる道具(ci_status など)も渡さず、リーダーへの指示も「GitHub の CI の失敗は理由にしない」に変える。
- リーダーの手助け(ADR-0022)に、やることの無いチケットを取りやめる道具を足す。直すコードが無いチケットを保留にして責任者に回さない。
- 担当には、submit_pr のあとにどのコマンドが流れるかを伝え、先に手元で通しておくように頼む。
- リーダーの手助けと見回りには、最後のチームの CI の結果を見せる。

## 結果

- CI を待つ時間がなくなる。落ちる PR は、レビューの前に数分で戻る。
- GitHub Actions の利用枠を使わない。
- 手元で同じにできない確認(GitHub の秘密情報・GitHub が用意するサービス・別の OS)は流れない。それらが要るリポジトリは、コマンドを工夫するか、GitHub Actions の CI に戻す。
- リポジトリのブランチ保護で CI の確認を必須にしていると、GitHub が merge を断る。チームの CI を使うなら、必須の確認を外す。
- チームの CI はこの PC の資源を使う。1 度に 1 つずつ流すので、PR が多いと待ちができる。

## 検討した別案

- **両方通ってから merge する**: 安全だが、GitHub の CI を待つ時間は減らない。利用枠が止まると全部止まる。
- **小さいモデルのエージェントにコマンドを流させる**: 閉じ込めはそのまま使えるが、起動ごとにトークンを使い、結果をエージェントの報告に頼ることになる。
- **閉じ込めずに流す**: 速いが、エージェントが書いたコードをこの PC でそのまま動かすことになる。
