# ADR-0025: 承認のあとに戻ってきたら、その後の変更だけを確かめる。範囲外の指摘は merge のときに 1 回だけチケットにする

- 状態: 提案
- 日付: 2026-11-12

## 背景

確認(レビュー・セキュリティ・QA)がすべて済んで merge を待っていたチケットが、main との衝突や CI の失敗で開発に戻ると、直したあとに確認を最初からやり直していた。実際の記録では、CI の失敗で戻るたびに 3 つの確認をやり直し、#90 は確認を 72 回、#12 は 42 回受けていた。

さらに、確認のたびに範囲外の指摘(followups)が別チケットになり、同じ内容のチケットが何枚もできた(#12 から 35 枚、#90 から 28 枚。「手で押す保存で 412 が出たときの文言」だけで 5 枚)。それらの多くが #12・#90 の後に並び、待ちの列が伸びていた。

## 決定

- merge 待ちに入ったとき、その時点のコミットを「承認済み」として覚える。
- 承認済みのチケットが(衝突・CI の失敗などで)戻ってきて開発が報告し直したら:
  - 承認のあとに自分で足した変更が無い(main を取り込んだだけ)なら、確認をせずに merge 待ちに戻す。
  - 足した変更があれば、最初の確認の工程が、承認のあとの自分の変更(`git log --no-merges -p <承認済み>..HEAD ^origin/main`)だけを確かめる。承認なら、ほかの工程はやり直さずに merge 待ちに戻す。
  - 確認役が差し戻したときの直しは、今まで通り差し戻した工程に戻る。
- 範囲外の指摘(followups):
  - 確認する人に、開いているチケットの一覧を見せる。同じことを扱うチケットがあれば `existing` にその番号を書き、そのチケットのメモに足す(新しいチケットは作らない)。
  - それ以外は控えておき、PR が merge されたとき(またはすでに main に入っていたとき)に、まとめて 1 回だけ別チケットにする。同じタイトルは 1 つにする。
- リーダーは交通整理で、重複しているチケットを `drop_as_duplicate` で片付けられる。まだ開発に取りかかっていないものだけ。中身は残す方のメモに、待っていたチケットは残す方を待つように移す。

## 結果

- 衝突や CI の失敗で戻るたびに確認を 3 回やり直すことがなくなり、1 回の軽い確認か、確認なしで済む。
- 確認をやり直しても、同じ範囲外の指摘でチケットが増えない。merge されなかった PR の指摘はチケットにならない。
- 承認済みのコミットを覚え始めるのはこの変更から。今あるチケットは、次に merge 待ちに入ったときから効く。
