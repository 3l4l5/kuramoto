# ADR-0043: 連絡経路を編成に持ち、島への質問・相談は経路があるときだけ届け、無ければリーダーに回す

- 状態: 提案
- 日付: 2026-11-14
- チケット: #6(経路の保存と質問の道具)・#35(やりとりでの見せ方)・#54(リーダーの答えを残す)

## 背景

島(ADR-0019)の担当が、別の島の人に聞きたいことは出る(例: 開発がセキュリティに「この書き方は許されるか」)。それまでは、聞く道具も、誰が誰に聞いてよいかの決めも無く、担当は憶測で進めるか、責任者に聞くしかなかった。誰にでも聞けるようにすると、質問が行き交って起動が増える(ADR-0002: 待っている間はトークンを使わない)。

## 決定

- **連絡経路は編成の一部**として、島・流れ(ADR-0007)と同じ版で保存する。保存のときに `routes` を受け取り、**既定は連絡しない**。渡さなければ前の版を引き継ぐ。
- 道具「質問する」(`ask_island`)を担当に渡し、受信箱に `ask` を入れる。
  - 経路がある島なら、その島の **free(仕事を持っていない)人**が `reply` で答える。
  - **経路が無い相手への質問は、リーダーに回す**。
- リーダーに回った質問には、リーダーが `answer_question` で答える(#54)。答えは `ticket_questions.answer` に残り、チケットのやりとりの「答えを待っています」が消え、次の担当の指示に載る(`answeredBlock`)。リーダーの答えもやりとりに残すので、あとから「なぜそうなったか」を読める。
- 質問と答えは `ticket_questions` とチケットのやりとりに残す。**質問しても、チケットの担当・工程は変わらない**。答える起動の金額は、そのチケットに数える。
- やりとりでは、質問と答えを見やすい形にし、経路が無くてリーダーに回したものは「経路が無いのでリーダーに回した」という印で出す(#35)。
- 経路を変えた版は、生産性のフロー効率の推移の印になる(`flow.formationMarks`。ADR-0029 の追記)。オフィスの路線図(ADR-0055)には、経路を点線、答え待ちを封筒で出す。

## 結果

- 担当は憶測で進まず、決めた経路の中で聞ける。経路が無い相手の質問も、止まらずにリーダーへ届く。
- 質問のために担当・工程が動かないので、流れ(ADR-0044)を乱さない。
- 経路を増やすほど質問が増えて費用も増える。経路は、効果を編成の版ごとのフロー効率で比べて決める。

## 検討した別案

- **すべての島が自由に聞ける**: 質問が行き交って起動が増え、費用の見立てが立たない。経路を編成に持たせれば、版ごとに効果を比べられる。
- **経路が無い質問は断る**: 担当は返事が無いまま詰まるか、責任者に聞くしかない。リーダーに回せば、リーダーが答えるか、責任者に上げるかを選べる(ADR-0006)。
- **質問した担当に答えが来るまで待たせる(工程を止める)**: 答えを待つ間、チケットが止まる。答えは次の起動の指示に載せれば足りる。
