# ADR-0052: 定期レビューは「観点」を作って、何時間ごとに回し、見つけたものをチケットにする

- 状態: 提案
- 日付: 2026-11-14
- チケット: #89
- 詳しい設計: [docs/periodic-review.md](../periodic-review.md)

## 背景

画面のずれ・デザインシステム外の色や部品のような、「チケットが無いと誰も見ない」問題がある。チケットの流れ(ADR-0044)は、チケットになった変更の確認はするが、全体を定期的に見回る役割は無い。デザイナーによる画面レビューをはじめ、観点を自分で作って、決まった頻度で回したい。

## 決定

- **観点を持つ定義**(`periodic_reviews`: 名前・観点・頻度・担当の役割・対象・有効/無効)を、プロジェクトごとに作れる。SQLite 版 24・MySQL 版 24。`project_id` のスコープ・削除(ADR-0050)・SQLite → MySQL の移行にも入れる。
- **頻度は「何時間ごと」**で持つ(1〜8760。毎日 = 24、毎週 = 168)。cron 式にしない。始業・休業があるので、決まった時刻に回すより、前回から一定時間たったら回すほうが、取りこぼしても溜まらない。次の起動は `(last_run_at ?? created_at) + every_hours`。無効 → 有効に戻したら、そこから 1 頻度ぶん待つ。
- **担当は「役割」で指定する**(designer / qa / review / sec / lead)。特定のメンバーでなく、その役割の free の人が動く。
- **始業中の `housekeep`(見回りと同じところ)から起動する**。頻度が来た有効な定義ごとに実行の記録(`periodic_review_runs`)を作り、受信箱に `periodic_review`(チケット無し)を入れる。同じ定義の待ち・実行中の回があれば起動しない。取り残された回は、次の起動のときに error で閉じる。手動の「今すぐ実行」も同じ道(始業していなければ始業したときに動く)で、`last_run_at` を進める(次の定期の起動はそこから 1 頻度後ろになる)。
- **見つけたものは `create_review_ticket` でチケットにする**。種類は必ず付け、ずれ・不具合は bugfix が既定(ADR-0044)。**切る前に責任者の確認は挟まない**(チケットは交通整理を通って進む)。
- **重複は題名の近さで判定する**。開いているチケットの題名と、記号・空白を除いた 2 文字ずつの重なり(Dice 係数)が 0.7 以上なら切らない。LLM に判定させると費用が増えるため。本文・画面は見ない(足りなければ後で強める)。
- 初期の観点に「デザイナーによる画面レビュー」(`designer_screens`。毎週・デザイナー・全画面)をひな形で用意する。試作・お手本・デザインシステムを置き、`render_page`・`compare_screen` を渡す(ADR-0034)。

## 結果

- 画面のずれなどを、チケットを待たずに定期的に拾える。重複したチケットは切られない。
- 取り残された回で定義が詰まることはない。

## 検討した別案

- **cron 式で時刻を指定する**: 休業中に止まった回が、再開で一度に溜まって走る。
- **見つけたものを責任者に確認してからチケットにする**: 責任者の確認が増える(ADR-0006)。チケットは交通整理と各工程の確認を通るので、切ること自体は安全。
- **重複の判定を LLM に任せる**: 費用が増える。題名の近さで足りるうちは、機械的な判定にした。
- **レビューを工程(チケットの流れ)に入れる**: チケットにならない問題が拾えない。
