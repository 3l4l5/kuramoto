# ADR-0044: チケットに種類(feature/bugfix/refactor/docs)を持たせ、種類ごとの流れで進め、開発より前の確認は申し送りにする

- 状態: 提案
- 日付: 2026-11-14
- チケット: #4(種類ごとの流れ)・#8・#29(書き出し・読み込みで持ち越す)・#85(切り出しで種類を引き継ぐ)・#77(切り出しで画面・要件を引き継ぐ)

## 背景

どのチケットも同じ工程(開発 → レビュー → セキュリティ → QA → merge 待ち)を通っていた。ドキュメントだけの変更に QA は要らないし、バグ修正はセキュリティを飛ばしたくない、というように、必要な確認は種類で違う。一方で、開発より前のレビュー・セキュリティ・QA は、書かれたコードがまだ無いので、コードを見て指摘することができない。

## 決定

- チケットは**種類**(feature / bugfix / refactor / docs)を持つ。リーダーが `create_ticket` で付け、責任者は `POST /tickets/:id/kind` で変えられる(変えたらやりとりに残す)。
- 編成は**種類ごとの流れ**(工程の並び)を持つ。保存できない流れは zod で断る: 開発が無い・merge 待ちの前に工程が無い・同じ工程が 2 回ある。
- 次の工程は、今の版の流れから求める(`pipelineOf` / `nextStage`)。順は「チケットの種類の流れ → 既定の流れ → 今までの流れ」。島が無い工程・流れから省略した工程は飛ばす(言葉は ADR-0058)。工程を進むたびに今の版を読み直す。
  - 今の工程が今の流れに無いとき(島を外した・省略した)は、島で絞る前の流れで位置を探し、その後ろにある工程のうち今の並びにある最初のものへ進む。
  - 開発を通った(`dev_done`)チケットは、**開発より前の工程へ戻らない**。
- **開発より前の確認は申し送りにする**。開発より前のレビュー・セキュリティ・QA は payload に `preDev` を付けて起こし、コードを見ずに、開発へ渡す注意点だけを `leave_handoff` で `ticket_notes(kind='handoff')` に残す。開発のプロンプトに申し送りを入れる。リーダーの交通整理(triaged)を待ってから取り出す。
- **切り出しで引き継ぐ**。`split_and_retry`・見回りの切り出しで作ったチケットは、親の**種類**(#85)・画面・要件・リポジトリ・要件の項目を引き継ぐ(#77。`designSystem` は引き継がない)。`plan_refs` の `allScreens` を付けると、全画面の試作を渡せる。見回りで main の CI を直すチケットは bugfix で作る。
- 種類は、チケットの詳細・ボード(絞り込みと、種類の流れの順の列)・ツリー・生産性(絞り込み)に出す。書き出し・読み込みでも持ち越す(#29)。

## 結果

- 種類に合った確認だけが走るので、docs や refactor に不要な工程の費用が掛からない。
- 開発より前の確認が、コードの無い状態で空振りせず、開発の注意書きとして働く。
- 流れを変える編成の版が、フロー効率の推移(ADR-0029)で比べられる。

## 検討した別案

- **工程を全チケット共通のままにし、チケットごとに飛ばす工程を持たせる**: 飛ばし方がチケットごとに散らばり、編成の版で効果を比べられない。種類ごとの流れなら版にまとまる。
- **開発より前の確認を省く**: 設計の誤りを開発の前に拾えなくなる。コードを見ないで注意点だけ渡す形にすれば、空振りせずに残せる。
- **開発の後でも戻れるようにする**: 開発のやり直しと工程の往復が増え、回り続けの元になる(ADR-0026)。
- **切り出しで種類を持たない(既定の種類にする)**: 切り出した bugfix が feature の流れで動き、不要な工程が走る(#85 の不具合)。
