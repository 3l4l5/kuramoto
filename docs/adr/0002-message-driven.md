# ADR-0002: エージェント同士はメッセージで動かし、待っている間はトークンを使わない

- 状態: 承認
- 日付: 2026-11-07

## 背景

エージェントを常に動かし続けるとトークンがもったいない。既存の見回りの仕組み(GitHub のラベルをメッセージ代わりにし、シェルが定期的に見回る)には、手渡しが遅い・状態が散らばる・止める仕組みが無い、という弱点があった。

## 決定

- Kuramoto の DB に受信箱(messages)を置き、エージェント同士・人とのやりとりはすべてここを通す。
- **ディスパッチャ**(LLM を使わない普通のコード)が受信箱から 1 通取り出し、宛先のエージェントを 1 回だけ起動する。終われば終了する。
- 外側のループ(受信箱が空になったら次のチケットを渡す、など)もコードで回す。
- 止まる条件: 人の判断が要る / レビューの往復が上限 / チケットの予算切れ / 同じエラーで再試行が尽きた。
- GitHub を見に行くのは、システムの外で起きること(人のコメント・CI・merge)だけ。

## 結果

- 待っている間のトークンは 0。手渡しはすべて DB に残るので、画面はそれを表示するだけで済む。
- ディスパッチャとウォッチャーの信頼性(取りこぼし・二重起動)を Kuramoto が引き受ける。

## 検討した別案

- **GitHub のラベルをメッセージにする**(既存の見回りの延長): 手渡しがポーリング間隔の分だけ遅れ、状態がラベルと各所のファイルに散らばる。
- **エージェントを常駐させる**: トークンが待ち時間に比例して増える。
