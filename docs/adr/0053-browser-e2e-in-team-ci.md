# ADR-0053: 画面のブラウザ E2E をチームの CI で回す形 — 閉じ込めは広げず、外のブラウザに connect し、確かめるまでは既定で動かさない

- 状態: 提案
- 日付: 2026-11-14
- チケット: #93・#96(E2E を npm test に入れて CI で回す形と、そのブラウザの閉じ込めの判断)
- 関係: ADR-0020(作業場所の閉じ込め)・ADR-0028(チームの CI)・ADR-0042(npm test は SQLite と MySQL の両方)
- 実装: #93 の PR(`docs/e2e.md` に流し方・読み方がある)

## 背景

「押しても何も出ない」のような画面の壊れは、サーバー側の試験(`src/flow-e2e.test.ts`)では見つからない。Playwright の画面の E2E を `npm test` に入れて、チームの CI(ADR-0028)で merge の前に止めたい。しかし、チームの CI は `npm test` を閉じ込め(sandbox-runtime。ADR-0020)の中で流し、**閉じ込めの中では Chrome が起動できない**(プロファイル・ソケット・Crashpad の置き場所が書けない)。ブラウザのために書ける場所・読める場所・通信先を広げると、閉じ込め全体の境界が弱くなる(ADR-0020 は、描画をサーバー側で行うことで、同じ理由で境界を広げずに済ませた。ADR-0034)。

## 決定

- **`npm test` の閉じ込め(`src/project/confine.ts`)は広げない**。ブラウザのために書ける場所・通信先を足さない。
- **`npm test` に E2E の回を足す**(SQLite の回 → MySQL の回 → E2E の回。ADR-0042)。E2E の回は、使い捨ての MySQL の database を消したあとに、空いているポートで、画面を作り直して流す。全体は 12 分(`globalTimeout`)で止める。飛ばすスイッチは `KURAMOTO_SKIP_E2E_TESTS=1` だけ。
- **ブラウザは閉じ込めの外で別に立て、中のテストは connect する(案 b)**。チームの CI の runner(`SandboxRunner`)が、Playwright の設定があるリポジトリのテストのコマンドの前に、`chromium.launchServer()` を立て、`wsEndpoint` を `KURAMOTO_E2E_WS_ENDPOINT` で渡し、終わったら必ず閉じる。`playwright.config.ts` は、宛先が渡されたら launch せず `connectOptions` で connect する。
  - 立てる場所は、閉じ込めの外ではあるが、**ブラウザ専用の狭い閉じ込め**(書ける: Chrome のプロファイル用の一時ディレクトリだけ。読める: node のツールチェーン・リポジトリの `node_modules`・Playwright のブラウザの置き場所だけ。つながる: localhost だけ)の中にする。
  - 宛先が渡されたときは、ブラウザに繋がらないことも**失敗**にする(「確かめていない」で通さない)。
- **明示の設定が無いと、外のブラウザの経路は動かさない**。`KURAMOTO_E2E_CONFINED_BROWSER=1`(Kuramoto のサーバーの環境変数)のときだけ、ブラウザサーバーを立てる。**狭い閉じ込めで Chrome が実際に起動し、接続した側から外へ出られないか**を、Chrome が動く Kuramoto のサーバーで確かめていないため。この確かめ(`scripts/check-confined-browser.ts`)は責任者が流す: (i) E2E が通る (ii) 入口を壊すと落ちる (iii) `file://` で `~/.kuramoto` や `~/.ssh` を開けない・外のプロキシや外の URL に出られない、の 3 つが通ったら有効にする(別チケット)。**確かめていない狭い閉じ込めは、merge と同時に有効にしない**。終了コード 2(確かめられなかった)のときは有効にせず、別の形を考える。
- **起動できなければ、知らせて通す**。設定が無い(既定)・手元の閉じ込めの中など、ブラウザを起動できないときは、失敗にせず「⚠ ブラウザを起動できなかったので、画面の確かめは流していません」と大きく出して通す(`KURAMOTO_E2E_REQUIRE_BROWSER=1` で失敗にできる)。**狭い閉じ込めの中でブラウザが立たなかったときも、閉じ込めの無いブラウザには切り替えない**(同じく「確かめていない」で通す)。画面が壊れた失敗とは見分ける。
- 時間が収まらないときは、E2E を `npm test` から外し、プロジェクトの設定の CI コマンドに `npm run test:e2e` を別に足す。

## 結果

- 閉じ込めの境界は ADR-0020 のまま。ブラウザ専用の狭い閉じ込めが、閉じ込めの外のブラウザの出口を絞る。
- 確かめが済むまで、チームの CI の画面の E2E は流れず、そのことは毎回出力に出る(黙って通らない)。
- E2E の書き方・入口を足す手順は `docs/e2e.md` に残る。

## 検討した別案

- **(a) 閉じ込めの書ける場所・通信を広げて、中で Chrome を起動する**: 境界が弱くなる(ADR-0020 の決めに反する)。
- **ブラウザサーバーを閉じ込めの無い状態で立てる**: 接続した側(閉じ込めの中のテスト)が、ブラウザ経由で `file://` の読み出しや外への通信をできてしまい、閉じ込めの抜け道になる。狭い閉じ込めで立てると決めた。
- **狭い閉じ込めで立たなければ、閉じ込めの無いブラウザに切り替える**: 上と同じ抜け道になる。切り替えず、「確かめていない」で通す。
- **確かめずに、狭い閉じ込めを merge と同時に有効にする**: 起動できない・穴があることが、チームの CI で初めて分かる。確かめを責任者が先に流し、有効にするのは別チケットにした。
- **E2E を CI で流さず、手元だけで流す**: 画面の壊れが merge の前に止まらない。
- **ブラウザの起動に失敗したらテストを失敗にする**: 閉じ込めの中では必ず落ち、画面が壊れたのかが見分けられない。
