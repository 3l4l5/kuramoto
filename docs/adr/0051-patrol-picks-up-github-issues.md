# ADR-0051: 見回りで GitHub の新しい Issue を拾い、リーダーが振り分ける

- 状態: 提案
- 日付: 2026-11-14
- チケット: #79
- 関係: ADR-0030(既存のリポジトリの続きから始める)・ADR-0026(見回り)

## 背景

ADR-0030 は、既存のリポジトリの Issue を取ってくるのを**作ったときの 1 回だけ**にしていた(後から開いた Issue は拾わない。必要ならチャットでリーダーに頼む)。運用が続くと、GitHub に後から立つ Issue をチームが知らないまま溜まる。

## 決定

- 見回り(`patrol_min` ごと。ADR-0026)で、**サーバー側のふつうのコードが**開いている Issue を取り、`github_issues`(`project_id` のスコープ。SQLite 版 23・MySQL 版 23)に覚える。取得に LLM は使わない。
- **新しい Issue が無いときは、LLM(リーダー)を起動しない**(トークンを使わない)。
- 新しい Issue があるときだけ、リーダーの見回りを頼み、`create_ticket` の `issue` / `issue_duplicate` / `issue_to_owner` で振り分ける(チケットにする・重複として片付ける・責任者に任せる)。**どれも選ばなかった Issue は `passed` にして、二度は見せない**。結果はボードのやりとりに残す。
- チケットの詳細に、Issue へのリンクを出す。
- **Issue へのコメントは、設定 `issue_comment` を入れたときだけ書く(既定は書かない)**。外へ出る書き込みなので、責任者が明示したときに限る。
- 取得に失敗しても見回りは止めず、出来事に残して次の周期でやり直す。
- 試験は SQLite・MySQL の両方で流す(ADR-0042。GitHub はフェイク)。

## 結果

- 後から立った Issue も、見回りの周期でチームに届く。何も無いときは費用が掛からない。
- 同じ Issue を何度もリーダーに見せない。

## 検討した別案

- **Issue ごとに自動でチケットにする**: 重複・古い Issue・責任者に任せたいものまでチケットになる。リーダーが振り分ける。
- **ADR-0030 のとおり、作ったときの 1 回だけにする**: 後から立つ Issue が届かない。
- **GitHub の通知(webhook)で受ける**: 手元の Mac で動かす前提(ADR-0003)で、外から受ける口が要る。見回りの周期で取れば足りる。
- **取るのをリーダーの LLM に任せる**: Issue が無くても毎回起動する。取得は決まった処理で、振り分けだけを LLM にした。
