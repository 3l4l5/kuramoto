# ADR-0017: 書き出した設計書に復元用のデータを埋め込み、本部で読み込んでプロジェクトを戻す

- 状態: 承認
- 日付: 2026-11-08

## 背景

企画スタジオの中身は、設計書(Markdown)として書き出せる。書き出したものを別のマシンに持っていく・壊れた DB の代わりに使う・同じ企画から別の編成で作り直す、といったときに、Kuramoto がその設計書からプロジェクトを戻せるようにしたい。

## 決定

- 設計書の末尾に、企画の中身をそのまま JSON にしたもの(base64)を HTML コメントで埋め込む。GitHub などで開いても表示されない。形式には版(`kuramoto-export v1`)を付ける。
- 本部の「設計書から復元」で読み込むと、新しいプロジェクトを作って戻す。既にあるプロジェクトには上書きしない。同じリポジトリのプロジェクトがあっても、データの置き場所を分ける(`<repo>-2` など)。
- 戻すもの: リポジトリ、各段階の進め方・版・合意した版、要件、未決と答え(取り下げを含む)、フロー、画面(全部の案・選んだ案・合意・コメント)、インフラ、アーキテクチャ、ドメイン、データ設計、会話、Jira のキー、チケット(完了・取りやめはそのまま、それ以外は開発の受信箱に入れ直す)。
- 戻さないもの: 担当の会話の続き(ハーネスのセッション。そのマシンにしか無い)、途中の版の履歴、起動の記録と指標、PR の写し。書き出したときに作業中・順番待ちだった依頼も持ち越さず、中身の無い段階は担当を起こし直す。
- 本文(人が読む部分)を書き換えても、復元には反映されない。そのことを設計書に書いておく。

## 結果

- 設計書 1 つで、企画の状態を持ち運べる。
- 埋め込む分だけ設計書が大きくなる(画面の試作の HTML を含むため)。
- 形式を変えるときは版を上げ、古い版の読み込みを考える必要がある。

## 検討した別案

- **人が読む本文から逆算する**: 1 ファイルで済み、本文の書き換えも反映できるが、図の配置・画面の全案・コメントの位置などが失われ、書き方が変わるたびに読み取りが壊れる。
- **JSON を別のファイルで書き出す**: 仕組みは素直だが、2 つのファイルを一緒に持ち運ぶ必要があり、片方だけ残りやすい。
