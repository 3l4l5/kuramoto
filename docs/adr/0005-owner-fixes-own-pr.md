# ADR-0005: 実装と修正を分けず、PR の持ち主が自分で直す

- 状態: 承認
- 日付: 2026-11-07

## 背景

最初の案では「実装チーム」と「修正チーム」を分けていた。普通の開発チームでは実装した本人が指摘を直す。

## 決定

- 実装と修正は同じ「開発」の役割にする。レビューで差し戻されたら、PR の持ち主が自分で直す。衝突の解消も持ち主が行う。
- メンバーの実体はチケットごとのエージェントのセッション。直すときはそのセッションを再開する。
- 開発は「自分の PR の直し → 新しいチケット → 持ち主がいない・手が回らないものの引き継ぎ」の順に仕事を取る。
- 応援が画面から帰ってもセッションは残る。持ち主を呼び戻して続きから直せる。

## 結果

- 文脈を持ったまま直せるので、コードを読み直すトークンが要らず、再発も減る見込み。
- 時間が空いて再開すると、キャッシュが切れて文脈の読み直しにトークンがかかる。

## 検討した別案

- **修正専任の役を置く**: 毎回他人のコードを読むところから始まり、無駄が大きい。
