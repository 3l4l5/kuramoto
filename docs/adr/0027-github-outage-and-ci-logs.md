# ADR-0027: GitHub に入れないときはチームで待って自動で再開し、CI が落ちたら Kuramoto がログを取ってきて渡す

- 状態: 提案
- 日付: 2026-11-12

## 背景

実際のプロジェクトで、責任者の判断カードが次の 2 種類で埋まっていた。

- **gh の認証切れ**: Kuramoto が PR を作るときの `gh pr list` が `HTTP 401: Requires authentication` を返し、チケットごとに失敗 → リーダーの手助け → 保留になっていた(8 枚)。どれも原因は同じで、チケットの問題ではなかった。
- **CI が落ちて merge 待ちから戻り続ける**: 持ち主に返すのは「CI が失敗しています。直してください。」の一文だけだった。エージェントの作業場所からは GitHub(Actions のログ・PR の Checks)が見えないので、原因が分からず、何も変えずに出し直しては戻ってきていた(#72 は 20 回・起動 101 回、#84 は 17 回)。main 自体の CI が落ちていて、どの PR も通らないこともあった。

## 決定

### GitHub に入れないとき

- 起動のエラーが GitHub の認証エラー(401・Requires authentication・Bad credentials など)なら、チケットの失敗に数えない。プロジェクトを「GitHub に入れない」状態にして、責任者に 1 回だけ知らせる(リーダーとのチャットと、プロジェクトの画面の先頭)。
- その間は、チケットの仕事を取らない(企画・チャットなど、チケットを持たない仕事は動く)。自動 merge の見回りも止める。
- 間隔(設定 `github_probe_sec`、既定 60 秒)ごとに GitHub に入れるか(`gh api repos/<repo>` と `git ls-remote`)を確かめ、入れたら知らせて自動で再開する。
- 前に認証切れが理由で保留になったチケット(保留の文面に 401 などが入っているもの)も、入れるようになったら自動で再開する。
- 認証し直すこと(`gh auth login`)は Kuramoto にはできないので、責任者に頼む。頼むのは 1 回だけ。

### CI が落ちたとき

merge の前に CI が落ちていたら、Kuramoto が GitHub から落ちた確認と失敗したステップのログ(末尾 120 行・5000 文字まで。同じ実行は 1 回だけ)を取ってきて、次の順に決める。

1. 向き先(main)の最新のコミットでも同じ確認が落ちているなら、この PR のせいではない。持ち主に戻さず、「main の CI を直す」チケットを 1 枚だけ作り(ログつき)、PR は merge 待ちのまま待つ。
2. 同じコミットで初めて落ちたなら、一時的な失敗かもしれないので、落ちたジョブを 1 回だけやり直して待つ。
3. それでも落ちるなら、落ちた確認・リンク・ログを持ち主に渡して直させる。指示には「GitHub は見えない。ログは Kuramoto が取ってきたもの。何も変えずに出し直しても同じように落ちる。関係なさそうなら main を取り込む」と書く。

- ジョブが始まってもいない(ステップが 1 つも動かず、ログが無い)なら、上の 1〜3 より先に扱う。原因は請求・使用額の上限・アカウントのロック・ランナーなど、コードの外にあり、チームでは直せない。GitHub がジョブに付けた注記(「The job was not started because ...」)を取ってきて、リポジトリごとに 1 回だけ責任者に知らせる(注記から請求・上限と分かれば、Settings > Billing and plans を見るように書く)。持ち主にも「main の CI を直す」チケットにも回さず、merge だけ止める(開発と確認は続ける)。間隔(設定 `ci_probe_min`、既定 15 分)ごとに落ちたジョブをやり直して確かめ、ジョブが動いた・CI が通ったら知らせて再開する。
- 持ち主が CI の落ちたコミットのまま出し直したら、受け付けずに失敗として扱う。続けばリーダーの手助け(ADR-0022)に回る。
- 最後に落ちた CI のログは、リーダーの手助けと見回り(ADR-0026)の材料にも入れる。

### CI を調べる道具

エージェントの作業場所からは GitHub が見えないので、Kuramoto が外で gh を動かして答える道具を渡す。責任者に「ログを貼ってほしい」「やり直してほしい」と頼まないで済むようにする。

- `ci_status`(PR の CI の今。落ちた確認・ステップ・注記・ログの末尾・main の最近の実行)、`ci_run`(1 回の実行のジョブ・ステップ・注記・ログ)、`ci_settings`(秘密情報と変数の名前。値は見ない): PR のある開発、リーダーの手助けと見回りに渡す。
- `ci_rerun`(落ちたジョブのやり直し): リーダーの手助けと見回りだけ。1 チケット 1 時間に 3 回まで。
- 設定の変更・秘密情報の値は扱わない。

## 結果

- 認証切れでは、判断カードが 1 枚も増えない。責任者がするのは `gh auth login` だけで、あとは自動で戻る。
- CI の失敗は、原因の分かるログつきで持ち主に戻る。main が赤いときは PR を 1 枚ずつ戻さず、直すチケット 1 枚に集まる。
- CI が落ちるたびに、Kuramoto が GitHub にログを問い合わせる(落ちたときだけ)。
- この変更の前に「CI のログが見えない」で保留になったチケットは自動では再開しない(責任者が再開を押せば、新しい流れで進む)。
