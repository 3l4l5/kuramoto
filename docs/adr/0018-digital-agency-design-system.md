# ADR-0018: 画面の見た目をデジタル庁デザインシステムに合わせる

- 状態: 承認
- 日付: 2026-11-08

## 背景

画面は mock の見た目(独自の色・丸ゴシック・ダークモード)をそのまま使っていたが、見た目が微妙だった。一から作り込むより、公開されていて使いやすさとアクセシビリティが検討されたデザインシステムに乗りたい。

## 決定

- [デジタル庁デザインシステム](https://design.digital.go.jp/dads/)を使う。
  - トークン: 公式の `@digital-go-jp/tailwind-theme-plugin`(Tailwind CSS v3)と `@digital-go-jp/design-tokens`(CSS 変数)。
  - 部品: 公式のコードスニペット(React 版、MIT)から必要なもの(Button・Input・Select・Textarea・Checkbox・ChipLabel)を `ui/src/dads/` に写して使う。中身は変えず、Kuramoto 側の都合は呼び出す側(`ui/src/ui.tsx`)で合わせる。スニペットが前提にしているプラグインの v1 を使う。
- 文字は Noto Sans JP。色は key(青)・neutral・semantic のトークンを使い、画面の CSS の役割名(`--ink`・`--dev` など)はトークンに読み替える。
- デザインシステムに沿って、入力欄にプレースホルダーを使わず、例や説明は欄の外に書く。
- デザインシステムに暗い画面の定義が無いので、ダークモードはやめて明るい画面だけにする。
- 配置と振る舞いは今の画面(mock 由来)のまま変えない。作り直しのたびに E2E(ボタンの名前や文言で操作する)で動きが変わらないことを確かめる。
- オフィスの段階の帯や、必要なときだけ出るタブなど、スニペットに無い部品は、トークンを使って独自に作る。

## 結果

- ボタン・入力欄・フォーカスの見た目と、キーボード操作の扱いがデザインシステムに揃う。
- Tailwind CSS が入り、画面の CSS は「Tailwind のクラス(部品)」と「役割名を使った独自の CSS(配置)」の 2 つになる。
- ダークモードは無くなる。

## 後の変更

公式のスニペットは色と大きさを Tailwind のクラスで決めていて、役割名のトークン(`--line`・`--ink` など)を通らなかった。そのため `ui/src/dads/` は使わなくなって削除し、入力欄・選択・テキストエリア・チェックボックス・チップ・スイッチも、ボタンと同じ `ui/src/ds/` の部品(トークンだけを使う)に置き換えた。Tailwind は配置のクラス(`w-full` など)とトークンの参照に使い続ける。

## 検討した別案

- **トークン(CSS 変数)だけ使い、部品は自前の CSS で真似る**: Tailwind を入れずに済むが、部品の細かな振る舞い(押せないときの扱い・フォーカス)を自分で追いかけることになる。
- **Tailwind CSS v4 と プラグイン v2**: 新しいが、公式のスニペットが v3 と v1 を前提にしている。
- **ダークモードを独自に残す**: デザインシステムに定義が無く、色の対応を自分で決めることになる。
