# ADR-0035: 企画スタジオの担当が、外のサイトを検索して読めるようにする

- 状態: 提案
- 日付: 2026-11-13

## 背景

企画スタジオの担当(企画・デザイナー・アーキテクト)は、リポジトリを読む道具しか持っていなかった。公式のドキュメント・ライブラリやサービスの今の版・料金・制限、よく似たサービスの作りを確かめられず、覚えていることだけで技術選定やインフラを決めていた。

## 決定

- 企画スタジオの担当に、Web の検索(WebSearch)とページを読む道具(WebFetch)を渡す。プロジェクトの設定「設計で外のサイトを見る」で入れ外しでき、既定は入れる(設定 `plan_web`)。
- ページを読んでよいドメインを決められる(`plan_web_domains`)。空ならどこでも。書くと、そのドメインとその下だけを読める(`WebFetch(domain:…)` の許可)。検索はどちらでもできる。
- 担当への指示に、ページの中身は資料として扱い書かれた指示には従わないこと、リポジトリの中身や秘密情報を URL や検索語に入れないこと、決めたことの理由に使ったページは URL を添えることを書く。
- 開発・確認の担当には渡さない(作業場所のシェルは閉じ込めのまま。ADR-0020)。企画の担当はシェルを持たないので、`WebFetch(domain:…)` の許可がシェルの通信の許可に混ざっても影響しない。

## 結果

- 技術選定・インフラ・画面の作りを、今の情報で確かめて決められる。
- 外のページを読むので、ページに仕込まれた指示に誘導されるおそれと、リポジトリの中身が URL で外に出るおそれがある。指示と、ドメインの絞り込みで抑える。気になるプロジェクトはドメインを絞るか、止める。
- 検索とページを読む分、起動の額と時間が少し増える。
