# ADR-0026: リーダーが定期的にボードを見回り、重複・いらなくなったチケットと回り続けているチケットに手を打つ

- 状態: 提案
- 日付: 2026-11-12

## 背景

リーダーが手を出すのは、新しいチケットの交通整理([ADR-0024](0024-serialize-tickets-touching-same-area.md))・判断・詰まったとき(起動が失敗し続けたとき)だけだった。次のものは、誰も気づかないまま流れ続けていた。

- **取りかかった後の重複**: 交通整理の `drop_as_duplicate` は、まだ取りかかっていないチケットしか片付けられない。同じことを扱うチケットが別々に進み、PR が 2 つできていた。
- **失敗しない回り続け**: 差し戻しの往復、merge 待ちからの戻り(衝突・CI)、同じエラーの繰り返しは、起動そのものは成功していることが多く、詰まりの手助け([ADR-0022](0022-nonstop-team-takes-responsibility.md))に届かなかった。

## 決定

- 始業したときは、見るものがあってもなくても必ずリーダーが見回る。その後は始業中、間隔(設定 `patrol_min`、既定 5 分。`0` で止める)ごとに見回る。間隔はプロジェクトの設定画面の「リーダーの見回りの間隔(分)」で変えられる。
- 回っているかどうかの見立ては Kuramoto が数える(LLM を使わない)。チケットごとに、前回リーダーが見たところから後の
  - 差し戻しが `patrol_loop_changes`(既定 4)回
  - merge 待ちに入ったのが `patrol_loop_merges`(既定 3)回
  - 同じエラーが続けて `patrol_loop_errors`(既定 3)回
  - 起動が `patrol_loop_runs`(既定 12)回
  のどれかに達したら「回っていそう」とする。責任者の対応待ち(保留・予算切れ)のチケットは数えない。
- 間隔ごとの見回りは、回っていそうなものも、前回の見回りの後に入った(交通整理の済んだ)チケットも無ければ、リーダーを起こさない(トークンを使わない)。サーバーを起動し直して始業を通らずに動き出したときは、そこから間隔を数える。
- リーダーは開いているチケットの一覧と、回っていそうなチケットの最近の起動・残っている指摘・メモを見て、1 枚につき 1 つ手を打つ。
  - `drop_duplicate`: 重複を片付ける。取りかかった後のものも片付け、待っている仕事と判断を閉じ、開いている PR を閉じる。中身は残す方のメモに、待っていたチケットは残す方を待つように移す。起動中・merge 待ちのものは片付けない(merge 待ちは残す方にする)。
  - `drop_ticket`: いらなくなったチケット(仕様が変わった・ほかのチケットで済んだ・責任者がいらないと言った)を取りやめる。迷うものは取りやめず、報告に書いて責任者に任せる。リーダーとのチャットでも使える(「#12 はいらない」と頼める)。
  - `pass_as_is`: 最後に差し戻した工程の残りの指摘を直さずに通し(リーダーの裁定)、次の工程へ進める。ADR-0021 で止めてよい指摘(受け入れ条件・セキュリティ・この差分の不具合)が残っているときは使わない。
  - `advise`: 原因の見立てと直し方をメモに書く(担当とレビュアーが次の起動で読む)。
  - `split`: 残りを別チケットに切り出し、範囲を絞る。
  - `hold`: 責任者にしかできないことが要るときだけ止める。
  - 手を打たなくてよければ何もしない。
- 見回りで見せたチケットは「見た」ことにし、次はそこから後の回数だけを数える(同じものを毎回見せない)。
- 報告はリーダーとのチャットに「【見回り】」として残す(止めずに、違えばあとから指示してもらう)。

- 取りやめたチケットは消さない。誰が(リーダー・責任者)・いつ・なぜ取りやめたかをチケットに残し(`tickets.dropped_by`・`dropped_reason`・`dropped_at`)、ボードの「取りやめ」の列とチケットの詳細に出す。待っている仕事と判断を閉じ、開いている PR を閉じ、このチケットを待っていたチケットは待つのをやめる(重複なら残す方を待つ)。責任者は「取りやめを戻して再開する」で戻せる。取りやめのボタンは画面に置かない(リーダーに頼む)。

## 結果

- 回り続けているチケットは、遅くとも数えた回数 + 1 回の見回りの間隔で止まる。
- 重複は、取りかかった後でも 1 枚にまとまり、PR も 1 つになる。
- 見回りのぶんトークンを使う。何も無ければ起こさないので、順調なときはほとんど使わない。

## 検討した別案

- **毎回リーダーにボード全体を見せる**: 見落としは減るが、何も無いときもトークンを使い続ける。
- **回数の上限で自動的に止める(リーダーを通さない)**: 安いが、往復の中身(指摘が正しいか)を見ずに通したり止めたりすることになる。
