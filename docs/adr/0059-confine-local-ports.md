# ADR-0059: チームの CI の閉じ込めから、Kuramoto 本体のポートには届かせない

- 状態: 提案
- 日付: 2026-11-14
- チケット: #98(#93 のレビューで見つかった、今からある穴)・#101(担当のシェルから本体の API に届く穴。#102 と重複)

## 背景

`sandbox_strict_sockets` は既定が 0 で、閉じ込め(ADR-0020)は `allowLocalBinding` を許している。sandbox-runtime は、macOS では localhost の「どのポートにも」接続してよい規則を書くので、チームの CI(ADR-0028)の閉じ込めの中の `npm test` など(と、#93 のブラウザ専用の閉じ込め)から、Kuramoto 本体の API(既定 4300)に届く。
本体は、(#101 より前は)localhost からは合言葉なしで、`x-kuramoto: 1` のヘッダーだけで書き込めた(他のサイトからの書き込みを防ぐためのもので、閉じ込めの中のコードには意味が無い)。つまり PR のコードが、チケットの操作・merge などを本体の API 経由で行えてしまう。

## 決めたこと

**localhost は許したまま、Kuramoto 本体のポートだけ(と、プロジェクトの設定で足したポート)を断る。**

- 断るポート: `KURAMOTO_PORT`(既定 4300)・Kuramoto 自身の MySQL のポート(手元にあるとき。ADR-0060)と、プロジェクトの設定 `sandbox_deny_local_ports`(ポート番号を、改行・カンマ・空白で区切る。例: 本番の DB のポート)。
- 断り方: sandbox-runtime が書く `(allow network-outbound (remote ip "localhost:*"))` のすぐあとに、`(deny network-outbound (remote ip "localhost:<port>"))` を足す(Seatbelt はあとの規則が勝つ)。`wrapWithSandbox` が返すコマンドの中の規則を書き換える(`src/project/local-ports.ts`)。許可の規則が見つからなければ(sandbox-runtime の版で書き方が変わったとき)、緩めたまま流さずに止める。`@anthropic-ai/sandbox-runtime` は版を固定してあるので、上げるときはこの試験(`team-ci.test.ts`)が教える。
- 効く場所: チームの CI の閉じ込め(SandboxRunner)と、その中のブラウザサーバー(confined-browser.ts)。
- Linux の閉じ込めは、ネットワークの名前空間が別でホストの localhost には元から届かないので、何もしない。

## 選ばなかったこと

- **届いてよいポートだけに絞る(許可リスト)**: sandbox-runtime は、localhost を「全部許す」か「全部閉じる」かの 2 つしか選べない。ポートごとの許可は、規則を書き換えて足すことになるが、テストが自分で立てるサーバー(`listen(0)` で毎回ポートが変わる。Kuramoto 自身の `server.test.ts`・`flow-e2e.test.ts` など)・E2E・mysql-test(3307)に届かなくなる。ポートが前もって分からないので、許可リストは成り立たない。
- **本体の API に、閉じ込めから使えない認証を掛ける**(#98 では見送り、#101 で採用した。下の「担当のシェルから本体の API に届く穴(#101)」): #98 の時点では「この PC 自身(localhost)からは合言葉なしで使える」という使い心地を変える大きな変更だったので、ポートを断る方を先にした。この方法は、本体のほかのポート(DB など)や、他のローカルのサービスは守れない(守れるのは本体の API だけ)。
- **`sandbox_strict_sockets` を既定で 1 にする**: Chrome・E2E・mysql-test が動かなくなる(ADR-0042)。

## 残ること

- 断るのは名指ししたポートだけ。ほかのローカルのサービス(開発中のサーバー・DB など)は、`sandbox_deny_local_ports` に足さない限り、今までどおり届く。もっと強く閉じたいプロジェクトは `sandbox_strict_sockets` を 1 にする。
- macOS の Seatbelt の規則の書き換えは、実機(nested でない Kuramoto のサーバー)で `team-ci.test.ts` の「断るポート」の試験を流して確かめる(閉じ込めの中からは閉じ込めを重ねられないので、開発の閉じ込めの中では流れない)。

## 担当のシェルから本体の API に届く穴(#101)

**担当(エージェント)のシェル**は、Claude Code の閉じ込め(`@anthropic-ai/claude-agent-sdk` の `sandbox` 設定)で、localhost のポートを選べない(`allowLocalBinding` の真偽だけ)ので、上のポートの断りは効かない。そのままだと、担当のコードが本体の API(既定 4300)に届き、チケットの操作・merge ・設定の変更を API 経由で行えてしまう(責任者だけが merge する、というレビューの境目が破れる)。

### 決めたこと

**本体の API と画面のすべてに、閉じ込めの中から見えない合言葉を掛ける。localhost からも既定で必ず求める。**

- 合言葉は、起動時に `~/.kuramoto/access-token`(`KURAMOTO_HOME` の下。無ければ作る。権限 0600)を読む。`KURAMOTO_TOKEN` があればそれを使う。`start:public` が使っていたものと同じ仕組みで、`start` でも使う(`src/access-token.ts`)。
- 通すのは、Cookie か `Authorization: Bearer`(合言葉)。(Cookie には初め合言葉そのものを 1 年入れたが、担当の別ポートのサーバーに届いて漏れるので、**セッション ID(8 時間・失効できる)に替えた。ADR-0061**)合言葉つきの URL(`/?token=…`)を開くと、Cookie に入れて、合言葉を外した URL へ送り直す。API も画面(HTML)も、合言葉が無ければ 401(画面は「端末に出ている合言葉つきの URL を開いてください」の案内だけ。合言葉は一切載せない)。localhost も、`start:public` で開いた他の PC も同じ。書き込みには、これまでどおり `x-kuramoto: 1` も求める。
- 起動時に、合言葉つきの URL(`http://localhost:<port>/?token=…`)を端末に出す。責任者は、各ブラウザで一度開けば、(ADR-0061 のあとは 8 時間)合言葉なしで入れる。画面は、API が 401 を返したとき(Cookie の期限切れ・合言葉の作り直し)、上に「合言葉が通りません。端末に出ている URL を開いてください」を出す。
- **担当から合言葉を取れない作り**: ①合言葉のファイルがある `~/.kuramoto`(`KURAMOTO_HOME`)は、担当のシェルから読めない場所(ADR-0020)の中。②`KURAMOTO_TOKEN` は、担当に渡す環境から除き(`withoutHidden`)、閉じ込めの `credentials`(`hiddenEnv`)でも名指しで隠し、チームの CI のコマンド・ブラウザサーバーの環境からも消す。サーバーは、読んだあと自分の環境からも消す。③「localhost からなら合言葉なし」で合言葉を渡す道(HTML への埋め込み・API での配布)は作らない。そうすると担当も localhost で取れてしまう。合言葉は、端末に出る URL でしか渡さない。
- 試験: 合言葉なし・違う合言葉は 401(API・書き込み・画面)、合言葉つきの URL → Cookie → 通る(`server.test.ts`)、合言葉の置き場所・環境変数が担当に渡らない(`confine.test.ts`)、合言葉の読み書き(`access-token.test.ts`)、画面の案内(`e2e/auth.spec.ts`)。画面・server.test・E2E は合言葉を渡して呼ぶ。CLI(`src/cli.ts`)は DB を直接開いて API を使わないので、影響しない。

### 選ばなかったこと

- **SDK がポートを指定できるようになるのを待つ**: いつになるか分からず、それまで担当が本体を動かせるまま。しかも SDK の指定が入っても、担当のシェルしか守れない(他の入口の穴は別)。合言葉は SDK に依らず今すぐ効く。
- **合言葉を設定で入れる opt-in(既定は求めない)**: 既定では穴が残る。入れ忘れを責任者に任せる作りになる。
- **書き込みだけに合言葉を掛ける**: 読み取りの API(ほかのチケットの中身・設計・書き出し)が担当に見えたままになる。画面の読み込みを先に通すために合言葉の有無で見せ分けると、合言葉を渡す道(上の ③)に近づく。
- **担当のプロセスかどうかを、接続元で見分ける(ポート・PID)**: OS ごとに違い、壊れやすい。

### 残ること

- 担当のシェルから見えるのは、合言葉を「知らない」ことだけに頼る。合言葉が漏れる道(ログに出す・担当に渡す環境や作業場所のファイルに書く・`ps` で見える環境変数)は作らない。`KURAMOTO_TOKEN` は起動したサーバーの環境変数に入るので、同じユーザーのほかのプロセスから `ps` で環境が見える OS では、ファイル(既定)で使う方が安全。
- 責任者のブラウザの Cookie が、担当が立てた別ポートのサーバーに届く道は、ADR-0061 で扱う。ブラウザの Cookie が盗まれる(同じユーザーで動くほかのプログラムがブラウザのプロファイルを読める)と、合言葉も同じ。担当のシェルはホームの外を読めないので、ブラウザのプロファイルは読めない。
- 本体のほかのポート(DB など)は、このやり方では守れない(`sandbox_deny_local_ports` はチームの CI の閉じ込めだけ。担当のシェルには効かない)。SDK がポートの指定に対応したら、①担当のシェルにも `KURAMOTO_PORT` と `sandbox_deny_local_ports` を断る、②本体の合言葉は残すか(二重に守る。残すのが既定)を見直す。
- 合言葉の出し直し・ブラウザの追加を端末の URL の再表示で行うコマンドなど、使い心地の改善は別のチケット。今は、`~/.kuramoto/access-token` を読めば URL を作れる。
