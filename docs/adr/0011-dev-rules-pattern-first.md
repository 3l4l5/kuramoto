# ADR-0011: 開発ルールは形式で確かめられるものを優先する

- 状態: 承認
- 日付: 2026-11-07

## 背景

Jira の番号をそろえる、のような小さな決まりごとをプロジェクトごとに作りたい。

## 決定

- プロジェクトごとに開発ルールを作れる。中身は 名前 / 何を守るか / どこに効くか / 確かめ方 / 守れていなかったときの扱い。
- 確かめ方は「形式で確かめる(トークン 0)」を優先し、読まないと分からないものだけ「AI が読んで確かめる」。
- 守れていなかったら「持ち主が自動で直す」「レビューで指摘する」「直すまで先に進めない」から選ぶ。
- Jira のプロジェクトキーを設定でき、チケットは `SHOP-121` のような番号を持つ。
- 違反数と自動で直した数を計る。

## 結果

- 機械的に確かめられるルールは AI を使わないので、トークンもレビューの往復も増えない。
- 入力したルール名などは画面に出す前に必ずエスケープする。

## 検討した別案

- **すべてのルールを AI に読ませる**: 単純な書式の確認にトークンを使う。
