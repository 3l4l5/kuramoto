# ADR-0049: 終わったチケット(merge・すでに main に入っていた・取りやめ)の作業場所は、片付けた印を付けて消す

- 状態: 提案
- 日付: 2026-11-14
- チケット: #61(merge したチケット)・#68(すでに main に入っていた・取りやめにしたチケット)

## 背景

チケットごとに、役割ごとの作業場所(git worktree。`worktrees/<番号>-dev`・`-review`・`-qa` など)ができる(ADR-0020)。チケットが終わっても消されず、ディスクと git の worktree 一覧に溜まっていく。終わらせる道は、merge・「すでに main に入っていた」(`closeAlreadyDone`)・取りやめ(`dropTicket`)と複数あり、最初は merge の道だけ片付けていた。

## 決定

- **merge したチケット**: 開発・レビュー・QA など全役割の作業場所を消し、DB の `worktree_path` も外す(#61)。
- **すでに main に入っていた・取りやめにしたチケット**も片付ける(#68)。終わらせる道が多いので、道ごとに呼ぶのではなく、`dispatchOnce` で done・dropped のチケットのうち、まだ片付けていないものを**まとめて拾う**。起動中のチケットには触らない。
- **片付けた印は、`settings` の `worktrees_released:<チケット id>`** にする。「done・dropped で起動したことがあり、まだ印が無いもの」を拾い、`releaseWorktrees` が片付けたら印を付ける。`sessions.worktree_path` を目印にはしない(本番のコードでは書かれないので、何も拾えなかった)。
- 本番のループは `drain` なので、`drain` の `housekeep` のあとでも呼ぶ。
- 取りやめを戻す(再開)ときは、作業場所はまた用意される。終わったチケットとの会話の場所(`<番号>-chat`。ADR-0046)も、同じ道で片付く。
- 試験は `worktree_path` を手で入れず、`runs` と実際の流れ(`drain`)で確かめる。

## 結果

- 終わったチケットの作業場所が残らない。片付けは終わらせる道を問わない。
- 道が増えても(新しい終わらせ方を足しても)、拾う側の条件(done・dropped で印が無い)は変わらない。

## 検討した別案

- **merge の道だけで片付ける**: `closeAlreadyDone`・`dropTicket` の道で、`worktrees/<番号>-*` と `sessions.worktree_path` が残った(#68 の不具合)。
- **道ごとに片付けを呼ぶ**: 道が増えるたびに呼び忘れる。まとめて拾えば漏れない。
- **`sessions.worktree_path` を目印にする**: 本番では書かれない列で、試験では通るのに本番で何も拾わなかった。専用の印に替えた。
- **片付けず、ディスクの掃除を責任者に任せる**: 溜まったことに気づくのが遅れる。
