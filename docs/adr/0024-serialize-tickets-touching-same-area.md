# ADR-0024: 同じ場所を触るチケットは同時に開発しない

- 状態: 提案
- 日付: 2026-11-11

## 背景

島のメンバーが最大人数ぶんずっといるようになり([ADR-0023](0023-members-stay-at-max.md))、同時に進むチケットが増えた。そのぶん、先に merge された PR と衝突することが増えた。衝突すると、開発が main を取り込み、レビュー・セキュリティ・QA をやり直す。実際の記録では、衝突 1 回のやり直しに $6〜8 かかり、同じチケットで 4 回目の確認になったものもあった。

衝突した 2 枚(#21・#45)は、どちらも「CI でブラウザの画面を確かめる」チケットで、同じファイル `scripts/ci-screenshots.mjs` を書き換えていた。リーダーは交通整理で「先に終わらせるチケット」(after)だけを見ていて、「同じ場所を触るか」は見ていなかった。同時に進めずに順番にしていれば、避けられた衝突だった。

## 決定

- リーダーは交通整理(`plan_work`)で、チケットごとに **触りそうな場所**(`areas`)を書く。ファイルのパスか、機能のまとまり(例: 認証、メモ一覧)。主に書き換えるものを 1〜3 個。`package.json` のような、どのチケットも少し触る共通のファイルは書かない。
- 場所は大文字小文字・先頭の `./`・末尾の `/` をそろえて比べる。
- 触る場所が重なるチケットは、同時に開発しない。**先に開発に取りかかったチケットが merge(または取りやめ)されるまで、もう一方は実装を始めない。** 先の方が merge されたあと、新しい main の上で始めるので、衝突しない。
  - 「取りかかった」は、開発の起動がある、または実装の仕事を取り出し済みのどちらか。
  - もう取りかかっているチケットは止めない(直し・衝突の解消などは今まで通り進む)。止めるのは最初の着手だけ。
- 順番は先着で自動で決まる。どちらを先にしたいかが大事なら、リーダーは今まで通り after を書く。
- オフィスの「順番待ち」とボードには、「同じ場所(…)を触る #n の完了待ち」と理由を出す。

## 結果

- 同じファイルを触るチケットどうしの衝突と、それに続く確認のやり直しが減る。
- 同じ場所に仕事が集まっている間は、同時に進む数が減る。衝突 1 回のやり直しより、待つ方が安く、結果的に早く終わることが多いと見込む。
- 予想は外れることがある(書かれていない場所を触る、共通のファイルを触る)。そこで起きた衝突は、今まで通り持ち主に戻して直す。
- 場所が書かれていないチケット(この仕組みより前に交通整理したもの)は、誰も待たせず、誰にも待たされない。

## 検討した別案

- **リーダーに after で順番を書かせるだけにする(プロンプトで促す)**: すでに「同じファイルを触るものは after に」と書いていたが、守られなかった。after は「どちらが先か」まで決める必要があり、重いので省かれやすい。場所を書くだけなら軽く、順番は仕組みが決める。
- **実際の差分(変更したファイル)から衝突を予測する**: 着手前には差分が無いので、着手前の順番決めには使えない。
- **同じ場所の 2 枚を 1 人に続けて持たせる**: 担当の手が空くまで待つ点は同じで、別の島・別の人に回せなくなる。
