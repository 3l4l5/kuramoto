# ADR-0007: 役割と編成を分け、編成ごとのフロー効率で比べる

- 状態: 承認
- 日付: 2026-11-07

## 背景

どのような役割分担で実装させるのが効率が良いかを実験したい。将来は同じプロダクトを別の役割分担で作らせて比べたい。

## 決定

- 役割(開発・レビュー・セキュリティ・QA)と編成(島ごとの役割・最大人数・応援の条件、仕事の取り方)を分ける。編成はプロジェクトごとに画面から組み替える。
- 1 つの島に複数の役割を持たせれば兼任。各役割は 1 つの島にだけ置ける。開発は必須。
- 工程は編成にある役割から「開発 → レビュー → セキュリティ → QA → merge 待ち」の順に組み立てる。
- 兼任していても、自分が実装した PR は自分でレビュー・QA しない。
- 仕事の取り方は「下流優先」と「着手優先」を選べる。
- 編成は版で管理し、版ごとにフロー効率・リードタイム・トークン/完成・判断/完成・手戻り率を集計して並べる。

## 結果

- 編成を変えた前後で効率を比べられる。
- 編成を変えると席替えが起き、作業中のチケットは待ちに戻る(持ち主は名前で引き継ぐ)。

## 検討した別案

- **開発とレビューのチームを固定する**: 実験ができない。
