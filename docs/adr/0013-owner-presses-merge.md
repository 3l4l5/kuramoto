# ADR-0013: merge は責任者が画面から押し、押した瞬間と押した後に確かめ直す

- 状態: 承認(merge する人は [ADR-0022](0022-nonstop-team-takes-responsibility.md) で既定をチームに変えた。確かめ方はこのまま)
- 日付: 2026-11-07

## 背景

merge 待ちの PR を GitHub に移って merge するのは手間。一方で merge はリリースにつながり、取り消しにくい。

## 決定

- merge は画面(merge 待ちの棚・「あなたの対応」・リーダーの順番案内)から責任者が押す。AI は押さない。
- 押した瞬間に、merge できるか・CI が緑か・レビュー済みかを確かめ直す。だめなら merge せず持ち主に戻す。
- merge が終わったら、それをきっかけに残りの merge 待ちの衝突を確かめ直す。衝突したら原因の merge を添えて持ち主に戻す。
- 衝突の解き方で行き先を分ける: 機械的に解けたら merge 待ちへ、ロジックに手を入れたら差分だけ再レビュー、判断が要るならリーダー経由で責任者へ。
- 自動 merge は最初は持たない。数字を見て信頼できると分かってから設定で足す。

## 結果

- 往復が減り、merge の順番と衝突も画面で扱える。
- 衝突による手戻りを、レビュー指摘による手戻りと分けて数えられる。

## 検討した別案

- **小さな PR は AI が自動で merge する**: 最初から入れると、取り消しにくい操作を判断材料なしに任せることになる。
