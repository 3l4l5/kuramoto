# ADR-0006: 責任者には重い判断と merge だけを上げる

- 状態: 承認
- 日付: 2026-11-07

## 背景

責任者は画面に張り付いていたくない。何を求められているかが一目で分かる必要がある。

## 決定

- リーダーが判断を受ける。影響が小さいものは推奨で決めて「推奨で決めた点」として報告し、仕様・契約・セキュリティ・取り消せない操作だけを責任者に上げる。聞く範囲はつまみで変えられる。
- 責任者への判断カードには必ず次を載せる: 全体のどこの話か / 何を決めるか / 選択肢と推奨・理由 / 間違えると何が起きるか(戻せるか)/ 返事が無いとどうなるか / 証拠(GitHub の PR)へのリンク。
- 返事が無ければ期限で推奨に進む。
- 判断は画面の中で完結させ、GitHub は証拠を見に行くリンク先にする。答えた内容はリーダーが PR にコメントとして残す。
- 責任者の対応(判断と merge)は、オフィスの最上部「あなたの対応」と本部の一覧に常に出す。

## 結果

- merge される PR 1 本あたりで、責任者の注意を減らせる。
- 何を軽いとみなすかの線引きが、リーダーの方針に依存する。

## 検討した別案

- **判断のたびに GitHub に誘導する**: PR のコメントをさかのぼって論点を拾うことになり、何を決めるのかが分かりにくい。
